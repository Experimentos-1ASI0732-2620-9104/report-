##### 6.2.1.2. Code Quality & Code Security

<p>
En esta sub-sección se evalúa la calidad del código en términos de mantenibilidad y manejo de errores, y se revisan
posibles vulnerabilidades de seguridad (inyección, XSS, manejo inseguro de datos sensibles y dependencias vulnerables).
</p>

<p>
<strong>Calidad del código (backend):</strong>
</p>

| Hallazgo | Ocurrencias | Riesgo | Acción propuesta |
|---|---:|---|---|
| `PreserveStackTrace`: se lanza una nueva excepción sin conservar la excepción original (por ejemplo en `CreateBatchCommand`, `MaintenanceRecord`, `InventoryCommandServiceImpl`, `InventoryImportServiceImpl`, `EdgeGatewayApiKeyService`, `ExternalStripeService`). | 13 | Medio: se pierde la causa raíz en los logs, lo que dificulta el diagnóstico en producción (sección 7.4). | Pasar la excepción original como causa: `new IllegalArgumentException(msg, exception)`. |
| `GuardLogStatement`: llamadas al logger con concatenación de cadenas. | 55 | Bajo: costo de construir mensajes que no se registran. | Usar parámetros de SLF4J (`log.info("... {}", value)`). |
| `UseLocaleWithCaseConversions`: `toUpperCase()` / `toLowerCase()` sin `Locale`. | 7 | Bajo: resultados distintos según el idioma del servidor al convertir enumeraciones (`ApplicationError`, `CreateDeviationAlertCommand`, `DeviationAlertController`). | Usar `toUpperCase(Locale.ROOT)`. |
| `UnusedPrivateMethod`: métodos privados sin uso en las fachadas de contexto (`*ContextFacadeImpl`) y servicios externos. | 13 | Bajo: código muerto. | Eliminarlos. |
| `EmptyCatchBlock` en `BatchReportPdfRenderer`. | 1 | Bajo: el bloque está documentado e intencional (si las fechas no son válidas no se inventa una duración). | Mantenerlo; se marca como revisado. |

<p>
<strong>Seguridad del código:</strong>
</p>

<ul>
  <li>
    <strong>Backend:</strong> la categoría <code>security</code> de PMD (claves criptográficas embebidas, vectores de
    inicialización inseguros) no reportó hallazgos. Además, el acceso a datos se realiza con Spring Data JPA, por lo que
    las consultas son parametrizadas y no se construyen sentencias SQL concatenando datos del usuario.
  </li>
  <li>
    <strong>Web - <code>detect-object-injection</code> (18):</strong> son falsos positivos. La clave proviene de un tipo
    cerrado de TypeScript (por ejemplo <code>BATCH_STATUS_CHIPS[status]</code>, <code>ALERT_SEVERITY_CHIPS[severity]</code>,
    <code>PERIOD_ERROR_KEYS[error]</code>, <code>devicePaths[deviceType]</code>) o de un índice numérico de un arreglo, y no
    de un texto ingresado por el usuario, por lo que no es posible acceder a propiedades arbitrarias del objeto.
  </li>
  <li>
    <strong>Web - <code>detect-possible-timing-attacks</code> (2):</strong> falso positivo. La comparación
    <code>this.currentToken() !== token</code> se realiza en el navegador para descartar respuestas de una sesión
    anterior; no se compara un secreto en el servidor, que es el escenario donde aplica un timing attack.
  </li>
  <li>
    <strong>Web - <code>detect-unsafe-regex</code> (1):</strong> la expresión <code>FIRMWARE_VERSION</code> tiene un grupo
    repetido acotado (<code>{1,3}</code>) y valida un campo corto del formulario de dispositivos, por lo que el riesgo de
    ReDoS es bajo. Se registra como revisado.
  </li>
  <li>
    <strong>Web - XSS:</strong> no se encontraron usos de <code>innerHTML</code> con datos dinámicos. El único uso de
    <code>bypassSecurityTrustResourceUrl</code> está en <code>report-preview-dialog.ts</code> y se aplica a una URL
    <code>blob:</code> creada en el navegador con <code>URL.createObjectURL</code> para mostrar el PDF del reporte, no a
    una URL recibida del usuario. Angular escapa por defecto las interpolaciones de las plantillas.
  </li>
</ul>

<p>
<strong>Dependencias (npm audit) de la aplicación web:</strong> se reportaron 11 paquetes con vulnerabilidades
conocidas (1 crítica, 5 altas, 4 moderadas y 1 baja). Todos son dependencias de desarrollo: la cadena de build y

<code>@angular/build</code> y <code>vitest</code> a su última versión de parche y volver a ejecutar
<code>npm audit</code> en el pipeline.
</p>
